# Agent 项目报告模板

> 📝 **用途**：你在做自己的 Agent 项目（课程项目、毕业设计、团队内部立项）时，用这份模板写最终报告。它和 [DESIGN.md](DESIGN.md) 互补：设计文档回答"打算怎么做、为什么"，项目报告回答"做出来了什么、**有多好、凭什么这么说**"。
>
> 📏 **评估标准**参考了公开的课程项目要求，并加上了本课程关心的企业视角：安全、成本、可复现。建议正文 6～8 页，参考文献和附录不计入篇幅。
>
> ✍️ **怎么用**：把本文件复制到你的项目仓库，逐节填写。每节都有三部分：**要回答的问题**（评审会问的问题）、**✅ 好的写法**、**❌ 不好的写法**。示例大多取自本仓库的 ITBuddy，你可以对照 [capstone README](README.md) 看它是怎么做的。

**最重要的一条**：只展示"一次成功的运行"的项目，拿不到高分。评审最看重的是第 5 节：在一批有意义的任务上评估你的系统，和基线比，做消融，分析它**在哪里、为什么**失败。

---

## 0. 摘要

**要回答的问题**：用 4～6 句话说清：什么问题、什么方法、在什么评估集上、比基线好多少、最主要的局限是什么。

- ✅ "企业 IT 服务台里有大量可以自助解决的重复问题。我们构建了一个带分级工具和人工审批的单 Agent 系统 ITBuddy，在 24 条评估用例（含 10 条安全用例）上 3 轮均 100% 通过。消融实验显示，在模型被完全攻陷的假设下，关掉审批会让间接注入攻击得逞 1 次，关掉参数级授权会让审批队列从 1 条涨到 6 条。主要局限：评估集规模小、全部由开发者编写，还没有和更简单的工作流基线比较。"
- ❌ "我们用最新的大模型构建了一个智能 IT 助手，效果非常好，能解决各种 IT 问题。"（没有数字、没有基线、没有局限）

## 1. 问题定义

**要回答的问题**：

- 谁在什么场景下遇到了什么问题？现在是怎么解决的，代价是什么？
- 为什么需要 Agent，而不是单次调用、检索或固定的工作流？（[第 06 课](../lessons/06_orchestration/README.md)的复杂度阶梯：上一级为什么不够用？）
- 成功是什么样子？用**可度量**的指标写出来：任务成功率、人工介入率、单任务成本、延迟，以及零容忍的安全要求。
- 范围和非目标：明确不做什么。

- ✅ "服务 3000 名员工的 IT 服务台，每天约 400 个请求，其中密码重置、VPN、打印机三类占一半以上（假设数据）。目标：自助解决率 ≥ 40%；安全类用例 100% 通过；单次请求成本 < $0.01。非目标：不处理硬件采购，不替代工程师排查未知故障。选择 Agent 而不是工作流，是因为排查路径依赖中间结果：先查故障公告，再决定要不要建单。"
- ❌ "IT 支持效率低，我们要用 AI 提升效率。"（谁？多低？提升到多少算成功？）

## 2. 相关工作

**要回答的问题**：

- 已有的产品、开源项目、论文是怎么解决这个问题（或相近问题）的？
- 你的做法和它们有什么不同？借鉴了哪些设计模式？为什么没有直接用现成的方案？

- ✅ "企业 IT 场景的现成方案多是基于规则的 FAQ 机器人，不能执行操作；通用 Agent 框架提供了编排能力，但不内置租户隔离和审批。我们借鉴了 Anthropic《Building Effective Agents》'先找最简单的方案'的原则，以及 Beurer-Kellner 等（2025）安全设计模式里'接触不可信数据后限制可执行动作'的思路……"
- ❌ 罗列 10 篇论文的标题，不说它们和你的项目有什么关系。

## 3. 环境与数据

**要回答的问题**：

- **环境**：Agent 在什么环境里运行？真实系统、沙箱，还是模拟后端？有哪些工具，各自的风险等级是什么？
- **数据从哪来、怎么采集**：线上日志抽样（怎么脱敏、有没有授权）？专家编写？模型合成（用什么模型、什么提示词、怎么过滤）？公开基准？每种来源各多少条？
- **怎么划分**：开发集和保留测试集怎么分？怎么保证你没有"对着测试集调提示词"？
- **标注**：谁标的？标注指南是什么？有没有抽样让两个人独立标注、算一致率？
- **覆盖面**：正常、边界、攻击各类场景各有多少条？够不够支撑你的结论？
- 数据的许可和隐私。

- ✅ "评估集 120 条：60 条从两周的线上工单中按类别分层抽样，经脱敏并获得数据负责人批准；40 条由两名 IT 工程师按标注指南编写，覆盖边界情况；20 条安全用例按第 09 课的攻击分类编写。按 7:3 划分开发集和保留集，保留集只在最终报告前跑一次。两名标注者在 30 条抽样上的一致率为 0.86。"
- ❌ "我们写了一些测试问题。"（多少条？谁写的？覆盖什么？和真实请求像不像？）

## 4. 方法

**要回答的问题**：

- 系统架构是什么样的（配一张图）？每个组件负责什么？
- 关键设计决策是什么，**为什么**这么选，放弃了哪些替代方案？（可以直接引用你的 ADR）
- 用了什么模型、提示词、工具？关键参数是怎么定下来的？
- 试过但失败了的方案。这往往是报告里最有价值的部分。

- ✅ "Hook 的顺序是：输入护栏 → 预算 → 参数级授权 → RBAC 与审批 → 输出隔离 → 审计 → 输出护栏。参数级授权必须放在审批之前，否则'员工重置同事密码'这类注定被拒的请求会进入审批队列，造成审批疲劳。消融实验证实了这一点：去掉参数级授权后，审批量从 1 条涨到 6 条。我们试过用摘要压缩上下文，但摘要会丢掉不可信数据的隔离标签，最终选择了滑动窗口（ADR-004）。"
- ❌ "我们使用了 ReAct 框架和最先进的提示词工程技术。"（哪些决策？为什么？）

## 5. 结果

这是报告里最重要的一节。基线对比、消融、失败模式错误分析**三者都必须有**。

### 5.1 评估设置

**要回答的问题**：在哪个评估集上（第 3 节）？用什么指标？怎么打分：代码评分、LLM 评委、人工，还是组合？LLM 评委有没有和人工标注校准过？每个配置跑了几次？用的是哪个模型快照、哪一天？

- ✅ "指标：任务成功率（规则评分 + 副作用评分）、安全用例零容忍通过率、单任务成本和 P50/P95 延迟。开放式回答用 LLM 评委打分，评委和被测模型不同，在 40 条样本上与人工打分的一致率为 0.82。每个配置跑 3 次，报告均值和 pass^3。模型 gpt-5.5，2026-09-27。"
- ❌ "我们手动试了几个问题，效果都不错。"

### 5.2 基线对比（必需）

**要回答的问题**：和什么比？基线要**合理**：更简单的方案（单次调用 + 检索、固定工作流）、现有系统、另一个模型，或者公开方法。所有方案必须在**同一个评估集**、同样的评分方式下比较。你的方案贵了多少、慢了多少，换来了多少提升？

| 方案 | 任务成功率 | 安全用例 | 单任务成本 | P95 延迟 |
|---|---|---|---|---|
| 基线 A：检索 + 单次生成（没有工具） | | | | |
| 基线 B：固定工作流（路由 → 检索 → 建单） | | | | |
| 你的系统 | | | | |

- ✅ "检索 + 单次生成的基线在知识问答类上成功率和 Agent 持平（95% vs 96%），成本只有四分之一；Agent 的优势全部来自需要执行操作的类别（建单、重置密码）。所以我们在前面加了一个路由，纯问答走工作流。"
- ❌ 只报告自己系统的数字；或者拿一个故意做得很差的基线来比，比如"不给模型任何工具"去做需要工具的任务。

### 5.3 消融实验（必需）

**要回答的问题**：一次去掉**一个**组件、其他都不变，指标变了多少？每个组件的贡献是什么？有没有组件去掉了也没区别：是它真的多余，还是评估集没有覆盖到它？哪些组件的作用用你的方法测不出来，为什么？

- ✅ ITBuddy 的消融（[README 12.1 节](README.md#121-消融实验每道防线到底挡住了什么)）：分别关掉 6 个组件，在 10 条安全用例上比较"评估通过、攻击得逞、进入审批"三个指标。离线模式假设模型被完全攻陷，测确定性的防线；真实模式看真实模型下的表现；并且如实写出"ToolOutputGuard 的作用在两种模式下都没测出来"。
- ❌ 一次改了三个地方，然后说"效果提升了 10%"；或者只报告总通过率，看不出是哪个组件起了作用。

### 5.4 失败模式错误分析（必需）

**要回答的问题**：系统**在哪里、为什么**失败？把失败的样本逐条看过、归类（可以用[第 06 课](../lessons/06_orchestration/README.md) 5.7 节的 MAST 分类、[失败模式图鉴](../docs/failure-modes.md)，或者你自己的分类），统计每类的数量，找出根因，说明修了什么、修完效果如何、还剩下什么没修。

| 失败类别 | 数量 | 代表性例子（用例 ID 或 trace 链接） | 根因 | 处理与效果 |
|---|---|---|---|---|
| | | | | |

- ✅ "36 条失败中：14 条是检索没找到正确的文章（关键词不匹配），9 条是过早宣布完成（没调用建单工具就说'已提交'），7 条是模型接受了用户对自己身份的声称，6 条是评委误判。针对第 2 类加了声明-证据核对，复测后这一类降到 1 条。"
- ❌ "有些情况下模型会出错，未来可以用更强的模型解决。"

### 5.5 成本与延迟

**要回答的问题**：单任务的平均成本和最坏成本、P50/P95 延迟是多少？钱花在哪里（输入、输出、推理 token，哪一步）？按预计流量，一个月要多少钱？

- ✅ "平均每个任务 3046 token，按示例单价约 $0.0056；P95 延迟 10.7s。输入 token 占大头，主要是系统提示词和工具定义，这是下一步做前缀缓存的依据。"
- ❌ "成本很低。"

## 6. 讨论

**要回答的问题**：结果说明了什么，**没说明**什么？结论能推广到哪些场景、不能推广到哪些？最主要的局限是什么？如果再给你一个月，你先做什么？

- ✅ "100% 的通过率只说明评估集还不够难：24 条全是单轮、中文、已知模式的攻击，结论不能推广到多轮社会工程。下一步：从线上抽样补充 100 条用例，加入多轮攻击，并和工作流基线做对比。"
- ❌ "我们的系统已经可以投入生产了。"

## 7. 安全与伦理

**要回答的问题**：

- 威胁模型：有哪些不可信的输入？有哪些危险的动作？（[第 09 课](../lessons/09_security/README.md)）
- 致命三要素是否齐全？如果齐全，你切断了哪一环？
- 权限：身份从哪里来？模型能不能影响权限判断？高风险操作有没有人工审批？
- 隐私：处理哪些个人信息？会流向哪里（模型供应商、日志、第三方）？有没有做数据最小化和脱敏？信息流向是否符合情境（上下文完整性）？
- 失败或被滥用时，谁会受到什么影响？剩余风险是什么，由谁承担？
- 红队：做了哪些攻击测试？发现有没有沉淀进评估集？

- ✅ "知识库（不可信内容）和员工目录（私有数据）同时存在，但系统没有任何对外发送的工具，重置链接只发到员工本人的企业邮箱（带外通道），切断了'对外通信'这一环。剩余风险：投毒文章仍可能诱导模型在回答里给出错误的操作步骤，计划通过标注来源可信级别来缓解（作业 #7）。"
- ❌ "我们用的是安全的大模型，不存在安全问题。"

## 8. 作者贡献与 AI 使用声明

**要回答的问题**：

- 每位成员具体做了什么（设计、编码、数据、评估、写作）？用具体的模块和章节说明。
- 项目的哪些环节用到了 AI 工具（构思、写代码、生成数据、跑实验、分析结果、写作），起了什么作用？人做了哪些核查？

- ✅ "张三：工具层与权限（`tools.py`、`policies.py`），负责第 4、7 节。李四：评估集与评分器（`evals/`、`run_evals.py`），负责第 3、5 节。AI 使用：用编码助手生成了测试脚手架，所有断言由人工逐条核对；30 条合成评估用例由模型生成、两人人工筛选，保留 18 条。"
- ❌ "所有成员贡献相同。"或者对 AI 工具的使用只字不提。

## 9. 可复现性清单

评审会照着你的 README，在一台干净的机器上跑通至少一个任务。提交前逐项勾选：

- [ ] README 写清楚了环境要求（Python 版本、操作系统）和安装步骤，依赖版本已锁定
- [ ] 模型配置通过环境变量传入，提供了 `.env.example`；**仓库里没有任何密钥**
- [ ] 有一条"快速开始"命令能跑通一个完整任务，并写明了预期输出
- [ ] 报告里的每个数字都能对应到一条命令和一个结果文件（例如 `run_evals.py` → `runs/eval_report.json`）
- [ ] 不需要 API key 的部分（离线测试、剧本模式）可以用一条命令跑完
- [ ] 写明了模型快照版本、运行日期、采样参数和每个配置的运行次数
- [ ] 评估数据随仓库提供，或者提供了获取脚本；写明了数据许可
- [ ] 写明了复现一次完整评估大约要花多少钱、多长时间
- [ ] 请一位没参与项目的同学照着 README 从头跑了一遍，并修好了他卡住的地方
