# 课程编写规范（贡献者 & 维护者必读）

本仓库的目标：**让基础一般的开发者，在 4 小时内建立企业级 Agent 系统设计的完整心智模型，并且亲手实现每一层。**
每节课都必须同时满足"初学者看得懂"和"老手看了有收获"。

## 目录结构

```
lessons/NN_topic/
├── README.md          讲义（主体）
├── demo.py            可运行演示：默认调用真实模型；--offline 用 ScriptedLLM，无需 API key
├── exercise.py        练习（学员填写，TODO 处 raise NotImplementedError）
├── solution.py        参考答案（与 exercise.py 接口完全一致）
└── test_exercise.py   练习测试（离线、确定性；用 agentkit.testing.load_exercise 加载）
```

运行：`python lessons/NN_topic/demo.py [--offline]`，`make lesson N=NN`，`make test-solutions`。

## 写作原则

1. **先直觉后术语**：第一次出现的术语要中英对照并用一句大白话解释。
2. **每个设计决策都回答"为什么"**：不要只写"要加重试"，要写"不加会怎样、加错会怎样"。
3. **具体胜过抽象**：用具体数字、具体报错、具体场景。
4. **不编造**：引用的论文、博客、事故必须真实；不确定就不写。
5. **代码可运行**：文档中出现的命令和代码片段都要真实跑过。

## 课程分为两部分

| 部分 | 课程 | 占比 | 讲法 |
|---|---|---|---|
| 第一部分：基础构建 | 00–07 | 约 47%（约 140 分钟） | 概念 → 从零实现 → 练习 |
| 第二部分：企业问题与解决方案 | 08–16 | 约 53%（约 160 分钟） | **问题驱动**：真实问题 → 多种方案对比 → 适用场景 → 推荐选择 → 代码实现 |

## 企业问题卡片（第二部分每节课的主体格式）

第二部分的每节课由若干张"问题卡片"组成（每课至少 5 张）。每张卡片：

```markdown
### 问题 N：一句话描述企业里的真实问题

**场景**：具体到数字的真实场景（"一个 2000 人的公司，高峰期每秒 50 个请求，模型 API 限额每分钟 500 次……"）

**为什么难**：直觉方案为什么不行 / 会在哪里翻车

| 方案 | 怎么做 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|
| A. xxx | ... | ... | ... | ... |
| B. xxx | ... | ... | ... | ... |
| C. xxx | ... | ... | ... | ... |

**怎么选**：给出决策依据（规模、一致性要求、团队能力、成本），而不是"看情况"。
**本课实现**：本仓库代码实现了哪个方案（链接到源码），以及升级到生产级要换成什么（如 SQLite → Postgres/Redis）。
```
